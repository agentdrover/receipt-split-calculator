# Выпуск релиза

Как собрать и выпустить версию приложения. Подпись и публикация — локально,
ключ в GitHub не передаётся.

## Где что лежит

| Что | Где |
|---|---|
| Ключ подписи | `~/.android-keys/chekcalc-release.jks` |
| Пароль ключа | связка ключей macOS, служба `chekcalc-release`, учётная запись `keystore` |
| Переменные для сборки | `~/.android-keys/release-env.sh` |
| Ожидаемый отпечаток сертификата | `79:BF:65:FA:1E:CE:5C:9D:3F:04:EE:F8:E8:07:68:9C:43:49:EE:F7:97:03:2E:41:E8:5A:12:3F:71:D3:57:7F` |
| Версия | `app/version.properties` |
| Заметки о релизе | `docs/releases/<тег>.md` |

Пароль нельзя передавать аргументом команды: он останется в истории shell.
Скрипт берёт его из связки ключей сам; при ручном вводе — только `read -s`.
`set -x` при работе с ключом запрещён.

## Бэкап ключа

Ключ существует в одном экземпляре. Потеря ключа означает, что обновить
установленное приложение нельзя никогда.

1. Скопируйте `chekcalc-release.jks` в менеджер паролей или на внешний носитель.
2. Положите туда же пароль из связки ключей.
3. Раз в полгода проверяйте восстановление: разверните копию в отдельный каталог
   и выполните `keytool -list -keystore <копия>` — отпечаток должен совпасть
   с таблицей выше.

## Порядок выпуска

1. Поднимите версию в `app/version.properties`: `versionCode` только растёт,
   `versionName` — понятная человеку версия.
2. Допишите разделы в `CHANGELOG.md` и создайте `docs/releases/<тег>.md`.
3. `make -C app release-check` — дерево, версия, ktlint, тесты, lint. Ключ не нужен.
4. Слейте изменения в `main` через задачу хаба.
5. `make -C app release-verify` — SHA входит в `main`, CI на нём зелёный,
   тег и правила в порядке.
6. `make -C app release-build` — подписанный APK, сверка сертификата, файл
   доказательств `app/build/release-evidence.json`.
7. Установите APK на телефон и пройдите сценарий: ключ провайдера, фото чека,
   выбор позиций, итог, шаринг.
8. `make -C app release-draft` — тег на проверенный SHA и **черновик** релиза
   с APK, файлом суммы и заметками. Скрипт скачивает файл из релиза и сверяет
   сумму.
9. Проверьте черновик по чек-листу ниже и опубликуйте отдельной командой:
   `gh release edit v1.0.0 --draft=false`.

## Чек-лист владельца перед публикацией

- [ ] Скачанный из черновика APK открывается и устанавливается.
- [ ] `sha256` скачанного файла совпадает с файлом `.sha256` в релизе.
- [ ] Сертификат в `apksigner verify --print-certs` совпадает с отпечатком выше.
- [ ] Приложение запускается, ключ провайдера вводится, чек распознаётся.
- [ ] Итог сходится, кнопка «Поделиться» отдаёт текст.
- [ ] Заметки о релизе не обещают того, чего нет.
- [ ] Черновик не содержит лишних файлов.

## Переход с debug-беты

Бета подписана debug-ключом. APK с релизным сертификатом поверх неё не
устанавливается. Порядок: сохранить нужные итоги, удалить приложение, поставить
APK из релиза. `allowBackup=false`, поэтому локальная история чеков при удалении
теряется безвозвратно.

## Возобновление после сбоя

- Тег уже отправлен, черновика нет: `release-verify` увидит тег на том же SHA
  и разрешит продолжение; `release-draft` досоздаст черновик.
- Черновик есть, файлы не загрузились: удалите черновик,
  `gh release delete <тег> --yes`, и повторите с шага 8.
- Тег стоит на другом SHA: `release-draft` откажется работать. Правильный путь —
  новый `versionCode` и новый тег, а не перемещение тега.

## Плохой релиз

Опубликованный релиз не удаляется: ссылки на файл уже разошлись. Порядок:

1. Выпустите исправление с большим `versionCode` и новым тегом.
2. Пометьте прежний релиз в тексте: `gh release edit <тег> --notes ...`.
3. Если APK опасен, снимите его с релиза, оставив заметку.

Откат установленного приложения на меньший `versionCode` Android не разрешает.

## Почему Play отложен

Для новых приложений Google Play с 31.08.2026 требует `targetSdk 36`, а проект
собран на 35 с AGP 8.5. Переход требует обновления AGP и Gradle и проверки
поведения на Android 16 — это отдельная задача. До неё выпуск идёт через
GitHub Releases.

## Заметки о релизе

Для 1.0.0 заметки написаны руками: у PR ещё нет меток, а темы squash-коммитов
транслитерированы и обрезаны. С выпуска 1.1 работает генератор из заголовков PR
с метками `release:feature`, `release:fix`, `release:maintenance`, `release:skip`
(отдельная задача).
